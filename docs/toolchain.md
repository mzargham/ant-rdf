# The toolchain — install, layout, commands, compilers, verification

This is the reference for someone adopting `ant-rdf` as a tool: what is on disk, what every command does, which briefs a case gets, how to read a verification result, and where the design decisions are recorded. Concepts are in [primer.md](primer.md); running a session with an ethnographer is in [facilitation.md](facilitation.md).

## Install

```bash
git clone https://github.com/mzargham/ant-rdf && cd ant-rdf
uv sync                        # Python ≥ 3.11; rdflib, pyshacl, pydantic, typer, rich, pyyaml
uv run ant version             # ant-rdf 0.1.0
uv run ant verify              # SHACL Tier-1/2 + cross-refs over every case
```

`ant verify` on a fresh checkout exits 0 with a handful of **Tier-2 warnings** on the public cases (open questions the ethnographers have not yet answered — see [Reading a `verify` result](#reading-a-verify-result)). The `ant` command loads the ontology and instances relative to the checkout, so run it from inside the repository (the installed wheel does not ship `ontology/` or `instances/` — see [FUTURE_WORK.md](../FUTURE_WORK.md)).

## How the pieces fit

| Role | Lives in | What it does |
|---|---|---|
| **Model** | `ontology/material-semiotics-core.ttl`, `ontology/ant-prov-align.ttl`, `ontology/shapes/` | The vocabulary: classes, properties, SHACL constraints in three tiers, a founding-text citation on every term |
| **Controller** | `src/ant_rdf/` — the `ant` CLI | Authors deterministic Turtle from flags, an interactive prompt, or note/upload ingestion; validates; queries |
| **View** | `briefs/`, `wiki/` — generated by `src/ant_rdf/compilers/` and `src/ant_rdf/wiki.py` | Markdown briefs and a hyperlinked wiki, byte-stable for the same graph |

The CLI guarantees **structural correctness** (Tier-1 SHACL, cross-reference resolution, deterministic serialization); the ethnographer guarantees **content correctness** (**C7**). TTL, briefs and wiki are **never hand-edited** — every change goes through a command, then `ant refresh`.

## File layout

```
ant-rdf/
├── ontology/
│   ├── material-semiotics-core.ttl   # the vocabulary (CC0)
│   ├── ant-prov-align.ttl            # optional PROV-O alignment
│   └── shapes/                       # ant-shapes-core (Tier 1), -warnings (Tier 2), -lint (Tier 3)
├── instances/
│   ├── shared/                       # GLOBAL reference, reused across cases: practices.ttl,
│   │                                 #   agents.ttl, glossary.ttl (created on first use)
│   ├── waivers/                      # created by the first `ant waive add`
│   └── cases/<case>/
│       ├── shared/                   # PER-CASE frame-neutral home (`--perspective _shared`,
│       │                             #   ADR-0003): actants.ttl, inscriptions.ttl — no _perspective.ttl
│       ├── perspectives/<slug>/      # one directory per observer frame
│       │   ├── _perspective.ttl      # the ant:Perspective (auto-stubbed for `_default`)
│       │   ├── networks.ttl · actants.ttl · translations.ttl · moments.ttl
│       │   ├── characterizations.ttl · inscriptions.ttl · programs.ttl
│       └── uploads/                  # metadata for files registered by `ant ingest upload`
├── briefs/                           # compiled, derived — `ant refresh <case>`
├── wiki/                             # generated, derived — `ant wiki`
├── src/ant_rdf/                      # the package; compilers/ holds one module per DocumentKind
├── tests/                            # pytest; synthetic fixtures + the public cases
├── tools/gen_cli_reference.py        # regenerates the CLI reference below
├── adr/                              # decision records (README.md is the index)
└── docs/                             # this directory
```

Two "shared" directories, deliberately: `instances/shared/` holds vocabulary that is meaningful across cases (practices, agents, glossary terms); `instances/cases/<case>/shared/` holds a case's own frame-neutral records (an actant that several perspectives read; inscriptions), so every perspective-scoped compile includes it. None of the public cases uses a per-case `shared/` yet (their shared actants are re-declared per frame, which the Tier-1 identity guard keeps byte-identical).

## IRIs and slugs

Records are named `https://w3id.org/ant/cases/<case>/<kind>/<slug>` (`actant/`, `network/`, `translation/`, `moment/`, `char/`, `inscription/`, `program/`, `perspectives/`). Practices live at `https://w3id.org/ant/practices/<slug>`, agents at `https://w3id.org/ant/agent/<slug>`. By convention a perspective's slug equals the slug of the network it authors (`perspectives/architectural` ↔ `network/architectural`); a single-frame case may use `perspectives/_default` with any network slug. `ant query` accepts the bare slug wherever it is unambiguous.

## Authoring a case from scratch

The order matters because later records reference earlier ones (a dangling reference is a Tier-1 violation):

1. **Who is reading, from which practice** — `ant new-record agent`, `ant new-record practice` (both shared), then `ant new-record perspective --case <c> --held-by <agent> --grounded-in <practice>`. Skip this only for a throwaway single-frame case; without a grounded perspective the case gets no reader briefs.
2. **The network** — `ant new-record network --case <c> --perspective <p>`.
3. **Actants** — `ant new-record actant … --participates-in <network>`; `--perspective _shared` for an actant several frames will read.
4. **Moments, then the translation** — `ant new-record moment --kind …` ×4, then `ant new-record translation … --has-moment … --authored-under <perspective IRI> [--status] [--durability] [--traces-to-passage]`.
5. **Inscriptions** — `ant new-record inscription --class {inscription|immutable|fluid} --source …`; edges on actants with `--inscribes` / `--draws-on` / `--manifests-as`.
6. **Characterizations** — `ant new-record characterization --target <actant> --in-network <network> --role https://w3id.org/ant#<Role> --per-practice <practice> --invariance "…"`.
7. **Programs** (if contested) — `ant new-record program --opposes …` and `edit-record actant --has-program …`.
8. `ant refresh <c> --verify --wiki`, review the brief, revise through `edit-record`, commit the regenerated artifacts with the change.

The same records can arrive from a notes file (`ant ingest notes`, format in [notes-format.md](notes-format.md)) or the interactive prompt (`ant new-record interactive <kind>`) — plural ingestion, **C8**. The conversational version of this sequence is [facilitation.md](facilitation.md).

Notes on a few commands:

- `ant edit-record <kind>` set-replaces only the fields you pass and leaves every other triple byte-identical; `--clear-<field>` empties a multi-valued field; `--clear-status` / `--clear-durability` return a translation to *forming*.
- `ant remove-record` refuses while other records reference the target (listing them) unless `--force`; it never cascades. It requires confirmation in the LLM contract.
- `ant list --iri` always reads the full graph; `--case` / `--perspective` scope the census by file location.
- `ant compile <case> <DocumentKind>` prints to stdout without `-o`; `CaseCatalog` ignores `-o` and always writes `briefs/case-catalog.md`.
- `ant scope new` and `ant analyze list-methods` are **stubs** (acts 1 and 3 of the four acts, ADR-0000 R5); they print a message and do nothing.

## DocumentKinds — what `ant compile` and `ant refresh` produce

Sixteen compilers are registered (`src/ant_rdf/compilers/__init__.py:REGISTRY`). `ant refresh <case>` writes the subset the case supports; `ant refresh <case> --plan` prints it. `ant compile <case> <Kind> [-o file] [--perspective <p>]` renders any one of them.

| DocumentKind | Output (`briefs/…`) | Written by `refresh` when | Public cases today |
|---|---|---|---|
| `NetworkBrief` | `<case>-network.md`, or `<case>-<perspective>-network.md` per named frame | always | all four |
| `CaseCatalog` | `case-catalog.md` (cross-case, pinned path) | always | — |
| `ReadingGuide` | `<case>-guide.md` — "start here", links every brief the case has | a perspective is grounded in a practice | koi, pi-learning |
| `CaseSynopsis` | `<case>-synopsis.md` — frames at a glance, readings, flips vs agreements | grounded | koi, pi-learning |
| `PositionalityLedger` | `<case>-positionality.md` — who holds each frame, from which practice, holding which invariant | grounded | koi, pi-learning |
| `Glossary` | `<case>-glossary.md` — the ANT terms the case uses (from the ontology) + external terms | grounded | koi, pi-learning |
| `OPPMap` | `<case>-opp-map.md` — obligatory passage points and their traffic | grounded | koi, pi-learning |
| `InscriptionsBrief` | `<case>-inscriptions.md` — produced by / drawn on by / also an actant | grounded | koi, pi-learning |
| `DurabilityDashboard` | `<case>-durability.md` — translations by status (incl. forming) and durability | grounded | koi, pi-learning |
| `CharacterizationCoverage` | `<case>-coverage.md` — which actants are read, which are bare | grounded | koi, pi-learning |
| `TensionsView` | `<case>-tensions.md` — flips, precarity, anti-programs, idle passages | grounded | koi, pi-learning |
| `PerspectiveComparison` | `<case>-comparison.md` — frames side by side, pivoted on the actant | two or more named perspectives | koi |
| `ActantAcrossFrames` | `<case>-actants-across-frames.md` — each shared actant, role by role, frame by frame | two or more | koi |
| `SameProgramTrace` | `<case>-same-program-trace.md` — one program read across frames | two or more | koi |
| `ActantProfile` | (on demand) one actant's characterizations | `ant compile` only | — |
| `TranslationTrace` | (on demand) one translation's four moments narrated | `ant compile` only | — |

A compiler opts into `refresh` by declaring `REFRESH_SUFFIX`, and optionally `PER_PERSPECTIVE`, `MIN_PERSPECTIVES` or `REQUIRES_GROUNDED`, at module level. Every brief in the reader set carries a footer linking the four hubs (guide, synopsis, positionality, glossary), and a test asserts that no link in `briefs/` dangles.

## Reading a `verify` result

`ant verify` runs SHACL over the union of every case plus the cross-reference check, and classifies findings in three tiers (**C7**, ADR-0000 R9b):

| Tier | Severity | Breaks the build? | Waivable? | Examples |
|---|---|---|---|---|
| 1 | `sh:Violation` | yes | never | a network without a label; a translation with no moment; a shared actant whose label drifted between frames (`ActantShape`); a dangling IRI (cross-reference) |
| 2 | `sh:Warning` | no (unless `--strict`) | with a justification | a characterization with no practice or invariance; fewer than four moments; a translation without `authoredUnder`; an unanchored translation; a program no actant carries |
| 3 | `sh:Info` | no (`--lint` only) | — | an ontology term without `dcterms:source` |

A warning names the **focus node** (the record), the **shape** (`https://w3id.org/ant#TranslationAnchoredShape`), and a **message** that says what to do, usually naming the CLI flag. The choice is always the ethnographer's: fix the data through the CLI, or record a waiver in their own words:

```bash
uv run ant waive add <shape-iri> <record-iri> --by <agent-iri> --justification "<verbatim>"
uv run ant waive list
```

For the two **connectivity** warnings (`TranslationAnchoredShape`, `ProgramCarriedShape`) walk the ordered triage before waiving: intent mismatch (revise the record) → missing data (author the connecting claim, or first the missing actant) → ill-formed (remove the record) → waive. It is spelled out in [facilitation.md](facilitation.md#the-connectivity-triage).

| Identifier | What it is | Where |

**The four acts** (R5) are the separable stages an analysis moves through: 1 scope selection, 2 query, 3 analysis, 4 documentation. A `Network` record is an act-4 artifact — the analyst's committed reading — not a container. Acts 1 and 3 have data shapes but no engine yet; `ant query` is act 2.
